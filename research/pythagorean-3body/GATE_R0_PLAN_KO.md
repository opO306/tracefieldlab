# Gate R0 계획 — 자체 이진 분수 구간 산술과 독립 검사 (2026-10-11)

> 상태: 계획(실행 전 봉인). 봉인 해시는 `GATE_R0_SEAL.json`에 둔다. 실행 뒤 수정 금지.

## 0. 쉬운 설명
- 오차 상자 적분기의 가장 밑바닥 부품을 만든다. **"이 값은 반드시 이 두 수 사이에 있다"를 보장하는 계산기**다.
- 비유(실제와 구분): 물건 길이를 잴 때 "약 3cm"가 아니라 "2.99cm 이상 3.01cm 이하"라고 적는다. 계산할 때마다 범위를 **반드시 넓은 쪽으로** 반올림해서, 진짜 값이 범위 밖으로 새지 않게 한다.
- 실제: 구간 [lo, hi]의 끝점을 (정수 가수) × 2^(지수)로 저장하고, 모든 연산 결과를 지정한 비트 수로 **바깥쪽으로** 반올림한다.

## 1. 목표와 비목표
- 목표
  - `research/pythagorean-3body/rigorous/dyad.py`를 기존 구간 라이브러리 없이 **직접** 구현한다.
  - **다른 세션**이 정확한 분수(Fraction)로 독립 검사기를 만든다.
- 비목표: ODE 적분(R1부터), Lohner, 성능 최적화, 다른 언어.

## 2. API (구현자와 검사자가 공유하는 계약 — 이것만 보고 검사기를 만든다)
- `set_prec(bits: int)`, `get_prec() -> int`. 기본 128.
- `DI(lo, hi=None)`: lo·hi는 int 또는 `fractions.Fraction`. hi가 없으면 점 구간이다. lo>hi면 `ValueError`. 생성 시 끝점도 현재 정밀도로 **바깥쪽** 반올림한다(lo는 내림, hi는 올림).
- 속성 `lo_q`, `hi_q`: 끝점을 **정확한** `Fraction`으로 반환.
- 연산: `+ - * /`(DI끼리, DI와 int/Fraction), 단항 `-`, `sqrt()`, `sqr()`(제곱; 0을 포함하면 하한 0), `__pow__`(음이 아닌 정수 지수), `contains(q: Fraction) -> bool`, `width_q() -> Fraction`, `hull(other)`, `intersect(other)`(비면 `None`).
- 나눗셈: 제수 구간이 0을 포함하면 `ZeroDivisionError`. `sqrt`: 하한 < 0이면 `ValueError`.
- 포함 계약: 모든 연산 op와, 입력 구간 안의 모든 실수 x(, y)에 대해 정확한 op(x, y)가 결과 구간 안에 있다. `sqrt`도 포함한다(정확한 제곱근이 무리수여도 포함해야 한다).
- 끝점 크기 계약: 결과 끝점의 가수는 `get_prec()` 비트 이하다.

## 3. 합격 기준 (실행 전 고정)
| ID | 기준 | 판정 |
|---|---|---|
| R0-S1 | 무작위 시험 ≥ 200,000건(연산·정밀도 {24, 53, 128, 300} 섞음, 입력 구간 안의 끝점·중점·무작위 유리수 점). 정확한 Fraction 결과가 출력 구간 밖에 있는 경우 | 위반 0 → PASS |
| R0-S2 | 경계 사례: 0, 음수, 0을 걸친 구간, 점 구간, 매우 큰·작은 지수(2^±2000), 정확히 표현되는 값, 반올림 경계(가수가 정확히 prec+1비트) | 위반 0 → PASS |
| R0-S3 | sqrt 포함: 결과 [a, b]에 대해 a ≥ 0, a² ≤ inf(입력), b² ≥ sup(입력)을 Fraction으로 정확히 확인 | 위반 0 → PASS |

| R0-T1 | 조임 정도: 출력 폭 ÷ 정확한 폭(점 연산이면 0으로 나누지 않도록 2^−prec·|값| 기준). 분포 보고 | 측정 보고 |
| R0-P1 | 연산별 속도(128비트, 1회당 μs) | 측정 보고 |

## 4. 독립성
- 구현 세션은 `dyad.py`와 자체 단위 시험만 쓴다.
- **검사 세션은 `dyad.py` 내부를 읽지 않고** 이 2절 API만 보고 `rigorous/check_dyad.py`를 만든다(Fraction 기준).
- 검사 세션이 먼저 끝나면, `dyad.py`가 생길 때까지 기다리지 말고 검사기와 자기 시험(가짜 구현으로 위반을 잡는지 확인)까지 끝낸 뒤 보고한다.
- 최종 실행(검사기 × 실제 `dyad.py`)은 둘 다 끝난 뒤 조율 쪽(설계자 대화)에서 한다.
