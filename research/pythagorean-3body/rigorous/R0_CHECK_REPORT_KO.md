## 2. 검사 항목 (모두 정확한 `Fraction` 기준, 부동소수점 없음)
입력 구간은 항상 **검사 대상이 돌려준 `lo_q`, `hi_q`(실제 저장된 끝점)** 를 기준으로 삼는다. 요청한 값이 아니라 저장된 값 기준이므로 생성자가 틀려도 연산 검사가 오염되지 않는다.

| ID | 검사 | 방법 |
|---|---|---|
| R0-S1 | 무작위 포함 | 연산 `+ - * /`(DI·DI, DI·스칼라, 스칼라·DI), 단항 `-`, `sqr`, `**`0–5, `sqrt`, `hull`, `intersect`를 정밀도 {24,53,128,300}에서 **200,000건**(seed 고정). 입력 구간의 끝점·중점·무작위 유리수 점마다 정확한 값이 출력 구간 안에 있는지, 그리고 입력 구간 전체의 정확한 값 범위(끝점 조합, 짝수 거듭제곱은 0 포함 처리)가 출력에 들어가는지 확인. 입력은 작은 정수·작은 이진 분수·분모가 큰 유리수·2^±2200 이동·가수가 prec±1비트인 값·0·점 구간·0을 걸친 구간을 섞어 생성 |
| R0-S2 | 경계 사례 | 코드의 `s2_scalars`, `s2_ranges`, `s2_exception_cases`에 명시: 0, ±1, 1/3·1/10 같은 비이진 유리수, 2^±2000과 3·2^1999·1/(3·2^2000), 가수가 정확히 p/p+1/p+2비트인 값(2^p−1, 2^p+1(동점), 2^(p+1)−1(올림수 발생), …)과 그 ±2^2000 이동, 1±2^−p 근방, 0을 걸친 구간, 0에 닿은 구간, 극소/극대 구간, 점 구간, 폭이 2^−(p+40)인 구간. 모든 쌍×모든 연산(정밀도별 약 1.6만 평가) + 스칼라 혼합 + 단항. **서로 다른 정밀도**(300→24, 24→300, 128→53, 53→128)에서 생성 후 연산하는 경우도 포함. 생성자가 **정확히 표현되는 값은 그대로** 두는지(`ctor_exact`)도 여기서 확인 |
| R0-S3 | sqrt 포함 | 결과 [a,b]에 대해 `a ≥ 0`, `a² ≤ inf(입력)`, `b² ≥ sup(입력)`을 `Fraction`으로 정확히 비교. 점 포함도 제곱 비교로 확인(무리수 제곱근을 근사하지 않음) |
| R0-S4 | 가수 비트 ≤ prec | 모든 결과(연산·생성자·hull·intersect)의 `lo_q`,`hi_q`를 검사: 분모가 2의 거듭제곱인지, 홀수 가수의 비트 길이가 prec 이하인지(정수는 끝의 0 비트를 지수로 보냄). 다른 정밀도에서 만든 입력의 `neg/hull/intersect/pow1`은 계약이 모호해 비트 검사 생략 |
| R0-API | 보조(계획 2절 계약) | 예외: 0 포함 제수→`ZeroDivisionError`(DI/DI, DI/스칼라, 스칼라/DI, 스칼라 0), 음수 하한 `sqrt`→`ValueError`(하한 0은 정상), lo>hi→`ValueError`(미세한 차이 포함). 타입(`Fraction`), `lo_q ≤ hi_q`, 입력 DI 불변, 기본 정밀도 128, `set_prec/get_prec` 왕복, `contains`(닫힌 구간·bool), `width_q`, `hull`(포함), `intersect`(빈 교집합→`None`, 아니면 정확한 교집합·입력 구간 안), `sqr` 하한 0 |

판정은 위반 건수 0이면 PASS. 무작위 건수가 200,000 미만이면 위반이 없어도 `INSUFFICIENT`(PASS 아님). 위반 목록에는 연산별 최소 반례(입력 크기 기준 가장 작은 3개)와 전체 최소 반례(정확한 분자/분모 포함)를 넣는다.
부가: R0-T1(조임 정도)은 `출력 폭 ÷ max(정확한 폭, 2^−prec·|값|)`의 분포(최소·중앙·p90·p99·최대)를 JSON에 보고한다(판정 아님). 분모를 `max`로 잡은 것은 계획의 "점 연산" 기준을 폭이 반올림 단위보다 작은 구간까지 넓힌 **내 해석**이다. R0-P1(속도)은 이 검사기 범위 밖이다.

## 3. 계약 해석 중 모호했던 부분 (설계자 확인 필요)
계획 문구만으로 한 가지로 정해지지 않아 내가 고른 읽기이다. 구현자가 다르게 읽었으면 **오탐처럼 보이는 위반**이 날 수 있다.
1. **정확히 표현되는 값은 생성자가 그대로 둔다** (`lo는 내림, hi는 올림` = 격자 내림/올림이므로 고정점). 구현이 안전하게 한 칸 더 넓히면 R0-S2 위반으로 잡힌다. 건전성(포함)에는 문제가 없지만 계획 S2 "정확히 표현되는 값"에 맞춰 엄격하게 읽었다.
2. **`sqr`은 0을 포함하면 하한이 정확히 0** (계약 문구). `x*x` 방식이면 R0-API 위반.
3. **스칼라가 왼쪽인 연산**(`1 - DI`, `Fraction / DI`)은 계약의 "DI와 int/Fraction"이 양쪽을 뜻하는지 불분명 → 미지원(`TypeError`)은 **위반이 아니라 경고**(`reflected_op_unsupported`)로만 기록한다. 지원하는데 틀리면 위반.
4. **`intersect`** 결과는 두 입력 구간 안에 있어야 한다고 읽었다(넓어지면 R0-API 위반). `hull`이 정확한 최소/최대가 아니면 위반이 아니라 경고.
5. **지수 범위 무제한** (가수 정수 × 2^지수, 지수 상·하한 언급 없음)으로 본다. 그래서 2^±2000을 정상 입력으로 쓴다.
6. 정밀도는 24/53/128/300만 쓴다. 더 작은 값(예: 2)이나 0/음수 `set_prec`은 계약에 없어 시험하지 않았다.

## 5. 한계 (미확인·약점)
1. **같은 사람이 정답 구현과 검사기를 만들었다.** 계약을 같은 방식으로 오해했다면 둘이 함께 틀려 통과할 수 있다. 3절이 그 위험이 가장 큰 곳이다.
2. 가짜 25개는 "내가 떠올린 결함"이다. 실제 `dyad.py`의 결함이 이 유형과 같다는 보장이 없다.
3. 무작위·경계 시험은 **증명이 아니다.** 통과해도 의미는 "이 시험 범위에서 위반 없음"이다(계획 7절).
4. `lo_q`/`hi_q`가 내부 값과 다르게 거짓으로 보고되면 검사기는 알 수 없다(내부를 보지 않는 설계의 대가).
5. 정밀도 4개, 지수 ±2200 정도, 연쇄 연산(여러 단계 누적) 미시험. ODE 단계(R1)에서의 장기 거동은 범위 밖.
6. 연산 입력은 모두 같은 `set_prec`에서 만든 것이 대부분이고, 정밀도가 다른 경우는 S2의 4쌍으로만 확인했다.
7. 구현 속도에 따라 실행 시간이 달라진다: 내 참조 구현(Fraction)은 약 110초(3개 동시 실행 중). `--time-limit`(기본 3,300초)이 넘으면 무작위 단계를 끊고 `INCOMPLETE`로 표시한다(PASS 아님).
8. 제외한 것: R0-P1 속도, sqrt의 T1(정확한 폭이 무리수), 계약에 없는 동작(음수 지수, 비정수 지수, 부동소수점 입력, 잘못된 `set_prec`).
